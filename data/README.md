# Data

Everything the agents read comes from this folder, either loaded into Postgres and federated by Zetaris (live) or
loaded into an offline SQLite copy (sample mode).

| Path | What it is | Committed? |
|---|---|---|
| [`seed/`](seed) | Summaries of real public data that shape the synthetic plant, plus the plant SOPs and OSHA clause excerpts | Yes |
| [`model_probe.json`](model_probe.json) | Which NVIDIA model really answered each Nightshift probe (`scripts/probe_models.py`) | Yes |
| `raw/` | Optional full downloads for rebuilding `seed/` (`app/data/fetch_sources.py`) | No |
| `sql/` | Generated SQL for `scripts/load_data.sh` | No (regenerated) |
| `cache/` | Offline SQLite copy for sample mode, built on first use | No (regenerated) |
| `memory/` | H-MEM state saved by a running server | No |

**Synthetic, labelled as such.** The hall, people, rosters, certifications, incidents, telemetry, andon pulls,
work orders and SOPs are generated by [`app/data/generate.py`](../app/data/generate.py) with seed 42, so every
build gives the same data. All people are fictional. No real company or personal data is used: the OSHA reports
are stored only as aggregated counts by event type.

**How to rebuild.** `bash scripts/load_data.sh` regenerates the plant from `seed/` and loads the four databases
(`fleet`, `hr`, `plant`, `ops`); `.venv/bin/python -m app.zetaris refresh` picks up the changes in Zetaris.
Rebuilding `seed/` itself from the original sources is optional: `pip install -r requirements-data.txt`, then
`python -m app.data.fetch_sources`.
